# Import boundary

`GlbImporter` is the first runtime import adapter. It accepts a bounded GLB v2 containing one mesh with up to the authoring submesh budget of triangle primitives, backed by one BIN buffer. POSITION is required; NORMAL, TANGENT and TEXCOORD_0 are retained when present and must use the same presence layout on every primitive. Primitive-local vertices are concatenated in order and their indices remain separate submeshes. POSITION morph targets become a mesh-pinned `MorphSet`, and `extras.targetNames` supplies optional names.

The adapter rejects skin bindings, mixed attribute or morph layouts, sparse accessors, unsupported component/type combinations and unknown GLB chunks before creating a graph. It returns a source hash and explicit warnings so a successful import is not mistaken for a complete avatar import. It does not infer a Blender vertex correspondence, reconstruct quads, or claim humanoid/VRM compatibility.

`GlbSceneInventoryReader` is the scene-level boundary for multi-mesh work. It keeps mesh, primitive, node-instance and skin source indices together with node world transforms without decoding or selecting geometry. The one-argument `GlbImporter.Read` and `GlbSourceSkinImporter.Read` APIs preserve the original one-mesh contract; callers that have chosen a source locator use `GlbImporter.Read(bytes, meshIndex)` or `GlbSourceSkinImporter.Read(bytes, meshIndex, skinIndex)`. Static instance selection can additionally use `GlbImporter.Read(bytes, meshIndex, instanceWorld)` to apply the selected node's affine frame to positions, normals, tangents and POSITION morph deltas. Selected mesh morph IDs include the mesh index, so same-named targets from separate resources cannot collide. The Workbench can publish selected candidates as separate native graph objects; graph-keyed rig sessions preserve each skinned candidate. Mesh merge and shared-asset output remain I04-B tasks.

`GlbSkinImporter` is the separate skin profile. It reuses the static geometry adapter after removing skin attributes from a cloned JSON tree, then maps one selected GLB skin's JOINTS_0/WEIGHTS_0 into `SkeletonDefinition` and `SkinBinding`. The one-argument API preserves the one-mesh/one-skin contract; a selected source locator uses `GlbSkinImporter.Read(bytes, meshIndex, skinIndex)`. It accepts up to 256 joints, one four-influence set, and general affine node/inverse-bind transforms. The full source frames are retained by `GlbSourceSkinImporter`/`SourceSkin`; the portable authored skeleton publishes head/tail data. JOINTS_1/WEIGHTS_1 and malformed or unweighted vertices are rejected before graph creation. The result keeps the original source hash and can be connected to the existing skeleton → skin-bind → pose → skin-deform graph nodes.

`VrmMetadataReader` is a metadata-only adapter for VRM 0.x (`VRM`) and VRM 1.0 (`VRMC_vrm`). It keeps the source hash, title/author, spec version, semantic humanoid-to-node mapping and a bounded expression inventory (name, preset/custom flag, morph/material bind counts and source morph binds) without introducing UniVRM into the authoring core. `VrmExpressionMapper.ResolveForSingleOwner` can resolve a one-mesh/one-owner expression set to the source-hash-stable IDs emitted by `MorphSet`; it rejects owner mismatches, out-of-range target indices and duplicate target binds rather than guessing. The Windows workbench exposes those mapped expressions as a one-click MorphDeform update with normal command/Undo behavior for the current import session. It does not apply material binds, spring bones, look-at or general VRM export.

`VrmExpressionSessionCodec` stores that mapped, source-independent expression list as a bounded deterministic JSON sidecar. The sidecar contains stable target IDs and weights only; it does not copy the original VRM or any private avatar asset.

`VrmMetadataReader` also reads a bounded SpringBone inventory. VRM 1.0 `VRMC_springBone` chains, joints, collider groups and sphere/capsule radius fields are normalized alongside VRM 0.x `secondaryAnimation` root groups and sphere colliders. The adapter validates node/index/radius budgets and duplicate references but does not simulate motion, apply rotations, or recreate runtime colliders.

`VrmSpringSession`／`VrmSpringSessionCodec` persist that inventory as `vrm-spring-session.nyaforge.json`. The workbench shows the restored chain/joint/collider counts after reopening a project. The sidecar is source-pinned and contains no VRM bytes or runtime simulation state.

The Windows workbench uses these adapters only from an empty project and creates a native Source → optional MorphDeform → Output graph. A skin import additionally creates Skeleton, SkinBind, an initial rest pose and SkinDeform nodes. The original file is read locally and is not copied into the public repository. VRM metadata/humanoid, general node transforms, normal/tangent morph deltas and export are separate adapters.
